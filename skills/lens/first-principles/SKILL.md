# 第一性原理

## 目标

让 AI 帮用户把一个被「惯例 / 类比 / 大家都这么做」支撑的想法，拆回到**不可再分的基本事实**，再从事实重新往上推理，看结论是否还成立。

## 立场 (Stance)

第一性原理很强，但它**贵且慢**——它要求你质疑每一个继承来的假设。所以不是所有事都该用它。

- **不该用的场景**：日常小决策（今天吃什么、用哪个库）。对这些用第一性原理只会让你瘫痪。惯例存在是有效率原因的，大多数时候照做就好。
- **真正值得用的场景**：当一个「大家都这么做」的前提，**一旦它错了、代价极大**时——比如你要 all-in 一个创业方向、要赌上一年时间、要做不可逆的选择。

**判断信号**：当你发现自己说「因为行业就是这样」「竞品都这么做」却说不出底层原因时，就是该用它的时刻。

> **边界（与 jtbd 区分，避免输出趋同）**：first-principles 质疑的是**方案/做法的形态**——「为什么要做这个功能、这个做法的前提成立吗」。它**不负责**分析「用户是谁、要完成什么任务」——那是 jtbd 的工作。两者同用时，first-principles 负责**砍掉拄来的功能/惯例**，jtbd 负责**定位真实任务与真竞品**；不要把两者都做成「质疑需求真伪」。

### 可迁移到哪（lens 层核心）

第一性原理不属于物理。它的本质是「剥离继承来的假设，回到事实重推」，因此能搬到：
- **创业决策**：「这个市场需要 X」——真的吗？回到「用户的根本痛点是什么」重推。
- **产品取舍**：「成熟产品都有这个功能」——你的用户真的需要，还是你在抄？
- **职业/人生选择**：「读完研究生才能找到好工作」——回到「我要的能力/资源，到底靠什么获得」。

## 使用流程

1. **说清结论**：先让用户把当前的想法/结论一句话说出来。
2. **挖支撑**：追问「你为什么这么认为？」对每个理由继续追问，直到他给出的是**类比/惯例**（「别人都……」）还是**事实**（可验证的、不依赖他人做法的）。
   - 之所以追问，是因为大多数人以为自己在推理，其实在复述惯例。
3. **剥假设**：把所有「别人都这么做 / 行业惯例 / 据说」标出来——这些是要被质疑的继承假设，不是事实。
4. **列基本事实**：只保留不可再分、可验证的事实（物理约束、用户真实行为、成本结构、时间）。
5. **从事实重推**：仅用这些事实，重新推导结论。看是否和原结论一致。
6. **给出落差**：如果重推后的结论与原想法不同，明确指出差在哪、那个被剥掉的假设是什么。

## 输出格式

```
【原结论】……
【被剥离的假设】（这些是惯例/类比，不是事实）
  - ……
【基本事实】（可验证、不依赖他人做法）
  - ……
【从事实重推的结论】……
【落差】原结论 vs 重推结论的关键差异 + 那个危险假设
```

## 示例

Input: 「我要做一个 AI 笔记 app，因为现在所有效率工具都在加 AI。」
Output:
- 原结论：做 AI 笔记 app。
- 被剥离的假设：「所有工具都在加 AI」（这是惯例，不是你的用户需要的理由）。
- 基本事实：用户记笔记是为了「之后能找到/用上」；AI 能降低「整理」成本但不降低「记录」成本。
- 重推结论：真正的痛点可能在「检索与复用」，不在「记录时有没有 AI」。
- 落差：你在抄行业动作（加 AI），而非解决用户根本痛点（找回信息）。危险假设：把「行业在做」当成「用户需要」。
