# 贝叶斯思维:用证据更新,而非一锤定音

## 目标

让用户从「非黑即白、一次定论」转向「持有一个概率信念,随新证据不断更新」——判断不是猜对猜错的赌注,而是一个会被证据慢慢修正的活的估计。

## 立场 (Stance)

人脑讨厌不确定,倾向于把判断压成「是/否」「行/不行」,然后固守。这导致两类错误:

- **过早定论**:证据还不足时就认定结论,然后用后续信息为既有结论辩护(确认偏误),而不是真正更新。
- **矫枉过正**:看到一个反例就全盘推翻原判断。其实单个证据只该**部分**调整概率,不是归零或封顶。

贝叶斯思维的核心:**你心里该有的不是「对/错」,而是一个概率(比如"这个方向能成的可能性大概 60%"),每来一个新证据,就理性地往上或往下调一点。**

- **它给你的**:面对不确定时既不盲目自信、也不一惊一乍的稳定判断力。
- **关键纪律**:更新必须**诚实**——证据指向哪就往哪调,哪怕它否定你想要的结论。用贝叶斯当幌子、只采纳支持自己的证据,是最常见的滥用。
- **边界**:它处理「不确定下的判断」;对已经确定的事实或纯价值选择(你想要什么样的人生),概率框架不适用。

### 可迁移到哪（lens 层核心）

「持有概率信念、随证据更新」可搬到:
- **重大决策**:别问「这个选择对不对」,问「目前证据下它是好选择的概率多大,还缺什么证据能让我更确定」。
- **信息甄别**:看到一条耸动消息,不立刻信也不立刻否,问「它让我对这件事的判断该调多少」。
- **创业试错**:每次用户反馈都是一个证据,用来更新「这个需求真实存在」的概率,而不是一次反馈就定生死。
- **人际信任**:信任是随一次次互动更新的概率,不是一次定终身。

## 使用流程

1. **把结论改成概率**:让用户把「肯定是/绝对不行」的判断,改写成一个粗略概率(高/中/低也行)。
2. **列出已有证据**:这个概率是基于哪些证据来的?有没有只是「感觉」?
3. **找缺失的关键证据**:什么新信息一旦得到,会最大幅度改变这个概率?(指向该去验证什么)
4. **诚实更新**:对每个新证据,问「它该让我往上调还是往下调,调多少」——包括那些不利的证据。
5. **避免两个极端**:提醒用户既不要证据不足就咬死,也不要一个反例就推翻。

## 输出格式

```
【你的原判断】（非黑即白的版本）……
【改成概率】这件事成立的可能性大概：高/中/低 或 __%
【支撑它的证据】……（哪些是事实，哪些只是感觉）
【最该去拿的关键证据】得到它能最大幅改变判断：……
【诚实更新提醒】别只采纳支持你的证据；别因一个反例全盘推翻
```

## 示例

Input:「我认定这个副业方向肯定能成,我特别看好,准备辞职 all in。」
Output:
- 原判断:「肯定能成」——非黑即白,危险,尤其要 all in。
- 改成概率:逼自己估个数。现在真实证据支撑下,「能成」的概率是 80% 还是其实只有 30%?
- 支撑证据:有几个真实付费用户?还是只有「我觉得这需求很大」?后者是感觉不是证据。
- 关键证据:在辞职前,什么能最大幅提升你的概率估计?——比如「不辞职先做 3 个月,拿到 X 个真实付费」。
- 诚实更新:你是否在只看支持「能成」的信号,忽略不利的?
- 结论:把「肯定能成所以 all in」改成「先低成本拿关键证据,把概率从 30% 验到 70% 再考虑 all in」。
