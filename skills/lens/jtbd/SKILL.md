# JTBD：用户到底雇你的产品做什么

## 目标

让 AI 帮用户从「这个产品有什么功能 / 用户是谁」转向「用户在什么处境下，会**雇用**我的产品去完成什么任务」——这才是需求的真正来源。

经典隐喻：人们买的不是 1/4 英寸的钻头，而是墙上 1/4 英寸的**洞**。

## 立场 (Stance)

JTBD 的价值是**把注意力从「产品」和「人群标签」拉回到「任务」**。

- **它擅长**：戳破伪需求、避免堆功能、找到真正的竞品（用户为完成同一任务可能用完全不同的东西）。
- **它的边界**：JTBD 解释「为什么用」，但**不替你做技术可行性和商业模式判断**。别指望它告诉你「能不能赚钱」。
- **常见误用**：把 JTBD 写成一句漂亮的口号就停手。真正的 JTBD 必须落到「处境 + 动机 + 阻碍」三件具体的事，否则只是换皮的功能清单。

**人口统计画像（25-35 岁白领）几乎总是错的起点**——同一个人在不同处境下要完成的任务完全不同。任务，不是人群，才是需求单位。

> **边界（与 first-principles 区分，避免输出趋同）**：jtbd 只看**用户处境 + 真实任务 + 真竞品**，**不质疑**方案的技术前提或功能形态（那是 first-principles）。如果你在问「用户到底要完成什么」，用 jtbd；如果你在问「为什么方案要长这样」，用 first-principles。两者联用时不要重复彼此的结论。

### 可迁移到哪（lens 层核心）

「看清对方真正要完成的任务」可以搬到：
- **营销文案**：不写「我们的功能」，写「你正卡在什么任务上，我们怎么帮你完成」。
- **服务设计**：医院、餐厅、客服——用户「雇用」这次服务完成什么？
- **个人职业定位**：公司「雇用」你这个岗位，到底要完成什么任务？把简历从「我会什么」改成「我能帮你完成什么」。

## 使用流程

1. **拦截画像**：如果用户给的是人群标签（年龄/职业/性别），先提醒：这不是需求，问他「这些人在什么**具体处境**下会想到用你的东西？」
2. **还原处境**：找出触发场景——用户在做什么、卡在哪、什么时刻产生了这个需求。
3. **挖任务**：问「在这个处境里，他真正想完成的是什么？」用「当……时，我想……以便……」的句式写出来。
4. **找真竞品**：问「为完成这个任务，他现在用什么凑合？」——真正的竞品往往不是同类产品（笔记 app 的竞品可能是「截图 + 微信发给自己」）。
5. **列阻碍**：完成这个任务时，用户当前的阻碍/痛点是什么——这才是你的产品该解决的。

## 输出格式

```
【用户给的（待修正）】人群标签 or 功能清单
【真实处境】用户在什么场景下产生需求
【Job（任务）】当 <处境> 时，我想 <动机>，以便 <结果>
【现在怎么凑合的（真竞品）】……
【关键阻碍】当前完成任务时最大的痛点 = 你该解决的
```

## 示例

Input: 「我要做一个面向 25-35 岁职场妈妈的育儿 app。」
Output:
- 用户给的：人群标签（职场妈妈），不是需求。
- 真实处境：晚上哄睡后、碎片时间、对某个具体育儿问题焦虑且不确定。
- Job：当深夜遇到孩子突发状况时，我想快速得到「可信、不吓人」的判断，以便决定要不要去医院。
- 真竞品：百度搜索（结果吓人）、家庭群问长辈（不专业）、挂号问医生（慢）。
- 关键阻碍：现有渠道要么不可信要么太慢——这才是产品该解决的，而不是「再做一个综合育儿社区」。
