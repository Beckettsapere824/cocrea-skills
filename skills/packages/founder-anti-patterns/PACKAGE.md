# 初创者避坑全流程包

## 这个包帮你做什么

把一个初创者从「埋头把东西做大做全」叫醒，按顺序问清四件事：
**你的想法基于事实还是惯例？用户到底要什么？你是不是在过度工程？最小该做什么？**
最终把一个模糊的大想法，收敛成「一个能验证最关键假设的最小动作」。

## 整体立场

我们相信**大多数初创者死于「做太多」，不是「做太少」**。

这个包的默认倾向，是帮你**做减法、找到「先别做」的理由**——这与 vibe coding 工具
「鼓励你快上、多做」刚好相反。我们让你慢一秒，把劲使在「验证」而不是「建设」上。

如果用完这个包，你的结论是「我应该先去做一个不写代码的最小验证」，那它就成功了。

## 包含的 Skills 与推荐顺序（自然语言工作流）

> 这套顺序不是我们的引擎在跑——是**你的 AI 读懂下面这段话后自己串起来执行的**。
> 加载本包后，对你的 agent 说「帮我看看我这个初创想法」，它会按此顺序走：

1. **first-principles**（方法）— 先剥掉「行业都这么做 / 竞品都有」的惯例假设，确认你的想法基于事实而非类比。
2. **jtbd**（方法）— 看清用户在什么处境下、要雇你的产品完成什么任务，戳破伪需求和人群标签。
3. **anti-over-engineering**（护栏）— 叫醒你：现在投入的复杂度，是用户验证过需要的，还是你在逃避验证？
4. **mvp-scoping**（工具）— 动手砍：围绕最关键假设，给出「现在做 / 推迟到以后」的清单 + 成功/失败信号。

**为什么是这个顺序**：先校准「想法的根基」（1-2 方法层），再「拦住过度建设的冲动」（3 护栏层），最后「落到可执行的最小范围」（4 工具层）。看 → 拦 → 做。

## 适用 / 不适用

- **适用**：有一个还没动手或刚动手、范围却已经很大的初创/产品/项目想法。
- **不适用**：已验证 PMF、要解决的是规模化/增长问题——那时你需要的是增长类工具，不是避坑包。
